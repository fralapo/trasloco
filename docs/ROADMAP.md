# Production readiness roadmap

Updated 2026-10-14. Version 1.4.0 is prepared and validated as a local release candidate on `codex/full-site-recovery`; it has not been pushed or published. It adds resumable authenticated encryption and decryption jobs to the 1.3.0 maintenance work. The local candidate passes the WordPress integration on PHP 7.4, 8.2 and 8.4, plus PHP 8.5 smoke and integration checks. This is not production certification. [The 2.0 execution plan](TRASLOCO_2_0_PLAN.md) contains the remaining feature increments; [branch reconciliation](BRANCH_RECONCILIATION.md) records how the separate draft implementation will be ported.

## Verified baseline

Release candidate `d9581af` passed [quality checks](https://github.com/fralapo/trasloco/actions/runs/38417080300) on PHP 7.4/8.2/8.4 and [six CLI integration jobs](https://github.com/fralapo/trasloco/actions/runs/38417080326) across those PHP versions with MySQL 8.0 and MariaDB 11.4. Those historical CI jobs downloaded WordPress at execution time and do not validate local changes made afterward.

On 2026-10-14, the complete CLI integration and same-site staged rollback rehearsal passed locally on PHP 8.5.4 with WordPress 7.1.3 and 6.9.10, and MariaDB 13.0.2. After peer-transfer changes, the full integration passed on PHP 7.4.33, 8.2 and 8.4 with WordPress 6.9.10 against both MySQL 8.0.46 and MariaDB 11.4.13. PHP 7.4.33 was installed keg-only from a community Homebrew formula that backports patches; upstream PHP 7.4 is end-of-life and this result checks compatibility, not production suitability ([PHP lifecycle](https://www.php.net/eol.php)). PHP 8.2/8.4 also passed on MariaDB 13.0.2, and PHP 8.5.11 passed on that MariaDB version, including administrator-only peer endpoints, resumed transfer and no-overwrite checks. Current WordPress 7.1.3 passed on PHP 8.4/MySQL 8.0. After adding durable offsite transfer jobs, the complete CLI integration passed locally on PHP 8.5/MySQL 8.0, exercising download queueing, expired-lease recovery, job payload safety, verified download and rejection of upload jobs by non-resumable providers. After adding scheduled encrypted offsite delivery and health alerts, the complete WordPress 6.9.10 integration and recovery rehearsal passed locally on PHP 7.4.33, 8.2.34 and 8.4.26 against MySQL 8.0.46 and MariaDB 11.4.13; PHP 8.5.11/MySQL 8.0.46 also passed. WebDAV protocol smoke tests pass on PHP 7.4, 8.2, 8.4 and 8.5, covering interrupted/resumed multipart uploads, read-back integrity, logical archive assembly and range reads. Storage smoke tests cover bounded retry after temporary upload/download failures and offsite download resume after interruption, including truncation of an incomplete trailing block. Optional WooCommerce 11.2.1 fixtures passed with HPOS enabled and with legacy order storage, preserving an order, refund, product line, custom metadata and order note through backup, SQL-failure recovery and restore replay. Anonymous HTTP fixtures returned 200 for a public page and 403 for an archive, its manifest, an arbitrary temporary file and plugin storage on Apache 2.4.67 and Nginx 1.31.6. These results cover local fixtures only, not production hosting or concurrent store writes.

The 2026-10-14 rerun after adding local incremental WP-CLI commands passed the full syntax scan, translation check and all standalone smoke tests. The end-to-end WordPress run reached the disaster-recovery rehearsal but could not finish because its temporary plugin copies exhausted local disk space; the integration script removed its temporary workspace on exit. This rerun does not replace the earlier completed integration results above.

- [x] Expiring operation-scoped tokens, administrator permissions and authenticated backup downloads.
- [x] Apache/IIS access rules for archives and private staging; Nginx configuration documented.
- [x] Encrypted HTTP Basic credentials using installation key material.
- [x] Serialized retried uploads, archive structural/path preflight, fail-closed SQL imports and symlink exports.
- [x] SHA-256 v1/v2 sidecars and resumable chunk-verification jobs.
- [x] Verification and offline-rescue compatibility for schema-1 SHA-256 sidecars from the preserved 2.0 feature branch; new archives continue to use the hardening v2 chunk format.
- [x] Persistent job ledger and leases, automatic backup settings, calendar-month scheduling, verified retention and failure notification hook.
- [x] CLI streaming encryption/decryption and independent encrypted rescue; administrators can encrypt verified copies and decrypt authenticated backups from the Backups page through durable jobs. Each worker handles at most four 1-MiB authenticated frames, seals stream state with the WordPress authentication salt, and resumes from flushed file offsets after interruption; the REST job response hides the sealed state. Local smoke and WordPress integration interrupt a job, reclaim its expired lease, resume it and verify exact plaintext bytes. Final structural inspection and checksum-manifest generation still scan the completed file in one worker request, and real-host proxy/WAF timeout testing remains open.
- [x] Read-only decryption compatibility for the preserved 2.0 branch's authenticated `TRLENC01` envelope; new encrypted backups keep the hardening `TRASENC1` format.
- [x] Verified pre-import recovery snapshots, independent receipts, clean-WordPress disaster rehearsal and manual database rollback after a real post-DDL SQL failure.
- [x] Independent two-phase file recovery with preserved originals; unknown destination files are not deleted. The read-only recovery comparison supports exact relative path/subtree exclusions without skipping archive validation or changing imports.
- [x] Administrator preflight/dashboard, archive preview and permission-scoped REST inventory/status; the archive preview maps recognized SQL table operations to destination names for supported single-site prefixes and reports whether a destination table exists. Selecting tables for selective restore can request a bounded raw-row comparison (up to 5,000 rows per table, 10,000 total, and 32 MiB of source row values); it requires matching schemas and primary keys, emits counts only, and never executes SQL. For comparable tables, an opaque live-schema/data fingerprint is checked again at import preflight to reject stale previews. It does not predict URL, serialized-value or table-prefix transformations and remains advisory; the fingerprint does not freeze writes during the import. WordPress 6.9+ also exposes the same bounded preflight as a read-only admin-only Abilities API ability.
- [x] WooCommerce live-export consistency warning with translation parity and rendering regressions for active/inactive WooCommerce. It advises pausing order writes; it does not create a database snapshot.
- [x] Authenticated WordPress-to-WordPress pull transfer with private resumable staging, bounded chunks, full-digest verification and no-overwrite archive/manifest publication. Local integration tests cover permissions, resume boundaries, idempotent completion and conflicting files; a standalone transport smoke test also runs in the quality workflow. See [peer transfer operations](PEER_TRANSFER.md).
- [x] Persistent offsite transfer jobs with credential-free payloads, lease renewal, durable byte progress, automatic recovery of interrupted workers and a bounded retry count. `wp trasloco offsite queue-upload <archive>` uses verified immutable WebDAV parts; `queue-download <archive>` uses private range checkpoints. Both have explicit retry commands. Local integration and WebDAV protocol fixtures check payload validation, expired-lease recovery, interruption/resume, integrity and no-overwrite behavior.
- [x] Local content-addressed snapshots of verified `.wpress` archives with independently reconstructible catalogs, chunk and whole-archive digests, private atomic publication, corruption rejection, no-overwrite materialization and explicit safe pruning. `wp trasloco incremental capture|verify|materialize|list|prune` exposes the local workflow; smoke tests cover the command path. Ordinary backups remain unchanged, and automated backup/retention and offsite object delivery are still open.

## Remaining production certification work

- [x] Local operator-driven full-site rollback rehearsal, including reviewed archive-absent paths. Production portability remains open and overlay recovery is not globally atomic.
- [x] Operator-guided recovery for a failed import: `wp trasloco restore-recovery` verifies and previews the exact pending receipt, then applies only with explicit confirmation; `wp trasloco prepare-recovery-files` stages and reviews the same receipt's files. Quarantine still requires reviewing the report and explicitly approving its fingerprint. This workflow is implemented and rehearsed locally; automatic or globally atomic rollback remains open.
- [x] Local process-lock contention regressions for browser-style export leases, WP-CLI/server backup jobs and offline file recovery; integration covers yielding and resuming one export owner while rejecting another, unsafe symbolic/hard-linked lock paths, and SIGKILL replay during SQL import.
- [ ] Cross-host/NFS fencing and storage-device power-failure injection. Local `flock` and `fsync()` tests do not prove remote filesystem or storage-controller durability.
- [ ] Real-host Apache/Nginx/IIS HTTP denial and authenticated restore tests; sessions replaced mid-import, WAF, disconnected uploads and large-host stress. Local Apache and Nginx fixture checks pass as recorded above.
- [x] Repeat the PHP 7.4/8.2/8.4 and MySQL 8.0/MariaDB 11.4 matrix after local changes. The complete local integration passes all six combinations with WordPress 6.9.10; the PHP 7.4.33 compatibility runtime is keg-only and carries community backports, while upstream PHP 7.4 is end-of-life.
- [ ] Remote storage/cloud adapters and incremental delivery on the canonical job/storage contracts. WebDAV stream storage, verified WP-CLI upload/download, immutable multipart upload resume, queued upload/download jobs, three-attempt temporary-error retries, a read-only inventory health command, private range-resumable downloads, opt-in scheduled encrypted WebDAV/S3 uploads and daily provider health alerts are implemented, with local protocol mocks and a real local-provider round-trip; no real WebDAV provider has been tested. The S3 adapter adds conditional single/multipart writes, exact range reads, bounded paginated inventory and provider-backed multipart resume for queued and scheduled encrypted uploads. AWS SDK command fixtures simulate interruption and replay through `ListParts`; a loopback HTTP fixture checks signed requests and wire responses. S3 requires PHP 8.1+. A local release builder creates and verifies base and S3-enabled ZIPs with the pinned runtime included. Local content-addressed snapshots are available through WP-CLI but are not yet integrated into scheduled retention or remote object delivery. Real AWS/S3-compatible provider and durability tests and other providers remain open; see [INCREMENTAL_BACKUP_DESIGN.md](INCREMENTAL_BACKUP_DESIGN.md).
- [ ] Consistency of WooCommerce/HPOS data while orders or scheduled actions are changing, plus other versions and order-related extensions. Pinned WooCommerce 11.2.1 restore fixtures for HPOS and legacy order storage pass locally. Multisite remains unsupported; a regression verifies network imports fail closed before importer metadata, files or database replacement.
- [ ] Complete keyboard, screen-reader, contrast and responsive accessibility audits, plus independent security review. Local fixes now trap Tab focus inside body-level dialogs, fit progress windows on narrow screens, show focus clearly and honor reduced-motion preferences. Manual browser and assistive-technology verification remains open.
- [x] Module-by-module reconciliation of draft PR #2 against all 30 exclusive commits and changed source files. Each feature module now has an explicit port, compatibility, retain or defer decision in [branch reconciliation](BRANCH_RECONCILIATION.md); the preserved branch is not merged wholesale.

Green CLI CI is necessary but does not prove complete disaster recovery or host compatibility. The local 1.3.0 release candidate does not claim those remaining certification results.

On the final local 1.3.0 candidate, the full WordPress integration and rollback rehearsal also passed on PHP 8.5.11/MariaDB 13 with WooCommerce 11.2.1 using both HPOS and legacy order storage. The large-archive verification fixture now drives every bounded continuation to completion, matching the production worker contract.
